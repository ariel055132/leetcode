# LeetCode Pattern Weekly

將指定的 LeetCode Pattern 整理成能協助「辨識題型、選擇方法、正確實作與日後複習」的實用筆記。重點是可轉移的解題思維，不是背誦單一題目的答案。

## 開始前

先從使用者提供的內容與對話脈絡確認：

- Pattern 名稱或本週主題
- 偏好的程式語言
- 筆記深度、格式與目標讀者
- 是否已有指定題目、草稿或錯題紀錄

若部分資訊未提供，合理推斷並直接完成；程式語言優先沿用對話脈絡，仍無法判斷時使用 Python。不要為了填滿格式而捏造使用者的個人錯誤或學習心得，改以「待補充」提示或提供可自行回答的回顧問題。

## 整理原則

- 先說明如何辨識 Pattern，再介紹程式碼模板。
- 用自己的話解釋核心狀態、狀態更新與 invariant。
- 明確區分適用情境、不適用情境及容易混淆的相似 Pattern。
- 模板應抽象且可重用；標示固定骨架與依題目調整的部分。
- 複雜度需說明成立條件，避免只列出結論。
- 代表題目應涵蓋入門、標準、變形或綜合難度，不追求數量。
- 若列出特定 LeetCode 題號、標題或當前題目狀態，無法確認時不要猜測；可請使用者提供題目，或明確標記待核對。
- 根據 Pattern 特性調整章節；不相關的章節可以省略。

## 建議工作流程

1. 用一句話定義 Pattern，指出它處理的問題結構。
2. 提取辨識訊號，包括輸入型態、題目要求、資料性質與限制條件。
3. 解釋核心思維：維護的狀態、更新方式、終止條件與 invariant。
4. 整理一套可重複執行的解題流程。
5. 提供通用程式碼模板，註明可變部分及複雜度。
6. 歸納重要變形，說明每種變形與基本版本的差異。
7. 選擇少量代表題目，對每題只記錄辨識理由、核心轉換及易錯點。
8. 列出常見錯誤與邊界條件。
9. 與相似 Pattern 建立簡短的選擇準則。
10. 加入自我檢查與間隔複習安排。

## 預設輸出結構

依照需求使用以下結構，內容簡單時可以合併章節：

```markdown
# [Pattern 名稱]

## 一句話定義

## 適用情境

## 不適用情境

## 題目辨識訊號

## 核心思維與 Invariant

### 維護的狀態
### 狀態如何更新
### 為什麼不會遺漏答案

## 解題流程

## 通用程式碼模板

### 固定骨架
### 依題目調整的部分
### 時間與空間複雜度

## 常見變形

## 代表題目

### 入門題
### 標準題
### 變形或綜合題

## 常見錯誤與邊界條件

## 與相似 Pattern 的比較

## 一分鐘速查

## 本週回顧

## 待複習項目
```

## 代表題目記錄格式

每題保持精簡，避免重寫完整題解：

```markdown
### [題目名稱]

- 辨識理由：
- 核心狀態或轉換：
- 最容易出錯的地方：
- 一句話解法：
- 複雜度：
```

## Pattern 比較方式

當兩個以上的 Pattern 容易混淆時，優先用小型表格比較：

| 判斷面向 | Pattern A | Pattern B |
|---|---|---|
| 適用資料結構 |  |  |
| 關鍵題目訊號 |  |  |
| 維護的狀態 |  |  |
| 選擇它的條件 |  |  |
| 不適用的情況 |  |  |

比較應形成可操作的判斷規則，例如「題目要求連續區間且視窗具有單調可調整性時，優先考慮 Sliding Window；需要任意區間和或處理負數時，再評估 Prefix Sum」。

## 一分鐘速查

在完整筆記最後濃縮成能快速複習的內容：

- 看到哪些訊號應想到這個 Pattern
- 最重要的 invariant
- 程式碼骨架的關鍵步驟
- 最容易出錯的更新順序或邊界
- 一個與相似 Pattern 的選擇規則

## 本週回顧問題

使用以下問題幫助使用者驗證是否真正掌握：

- 能否不看筆記寫出核心模板？
- 能否用一句話說明 invariant？
- 看到哪些訊號會想到這個 Pattern？
- 哪些變形仍容易混淆？
- 解錯時，問題出在辨識、建模、證明還是實作？
- 哪些題目應在 1 天、1 週與 1 個月後重做？

## 品質檢查

完成前確認：

- 筆記能回答「何時用、為何有效、怎麼寫、哪裡會錯」。
- 模板沒有綁死在某一道題目的變數或條件。
- invariant 與更新順序清楚且一致。
- 時間與空間複雜度正確，並包含必要前提。
- 相似 Pattern 的差異能轉化成實際選擇。
- 速查部分足以讓使用者在一分鐘內恢復解題思路。
