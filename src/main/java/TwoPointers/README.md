# Two Pointers Pattern

## 一句話定義

Two Pointers（雙指標）用兩個位置描述「尚未處理的範圍」或「各自的處理進度」，依照可證明的規則移動指標，避免重複枚舉已排除的候選。

重點不是程式裡剛好有兩個索引，而是能回答：**這次移動為什麼不會漏掉答案，也不會破壞已完成的結果？**

---

## 適用情境

- 已排序陣列中尋找兩數關係，能由目前的和或大小比較排除一端。
- 可以排序，且答案不依賴原始排列，例如計算符合條件的 pair 數量。
- 從兩端處理對稱位置，例如反轉字元陣列、判斷回文。
- 原地篩選、去重或搬移元素，以讀取指標與寫入指標維護有效前綴。
- 合併或比較兩個有序序列，各用一個指標追蹤尚未處理的元素。
- 鏈結串列的中點、環或固定距離問題，用快慢指標維護步數關係。

有序不是所有雙指標題的必要條件。回文依靠對稱關係；快慢指標依靠移動速度；部分最佳化問題依靠「一端已不可能得到更好的答案」。

## 不適用情境

- 無序資料上的 pair sum，且不能排序：不能只憑和太大／太小就移動端點，先考慮 HashMap。
- 題目要求原始索引、相鄰關係或連續區間：排序可能改變題意。若只需保留索引，可保存 `(value, originalIndex)` 後再評估成本。
- 無法證明某次移動排除的所有候選都不需要再看：兩個指標本身不能取代正確性證明。
- 要列出本身就有 `O(n²)` 個的配對：掃描可能壓縮計數，但不能把完整輸出的成本降為 `O(n)`。
- 想靠「和太大就縮小」處理含負數的連續區間：這種視窗規則通常失去單調性，應重新建模。

---

## 題目辨識訊號

| 題目訊號 | 優先考慮的指標分工 | 移動前要確認的性質 |
| --- | --- | --- |
| `sorted`、找兩數和、pair count | 左右相向 | 增加左值或減少右值，能否安全排除一批配對？ |
| 反轉、回文、左右對稱 | 左右相向 | 已處理的兩端是否已確定正確？ |
| `in-place`、保留順序、刪除／去重 | `read` / `write` 同向 | 寫入是否會覆蓋尚未讀取的元素？ |
| 兩個 sorted arrays／strings | 每個序列各一個指標 | 較小的一方能否確定不必再與目前另一方比較？ |
| 中點、cycle、倒數第 k 個節點 | 快慢或固定間距 | 指標之間要維持什麼速度或距離？ |
| 最長／最短連續區間 | Sliding Window | 能否維護整個視窗狀態，並安全移動邊界？ |

最後一列是雙指標的重要分支，但需要視窗內的 sum、frequency 等狀態；不能把每個左右指標題都當成 Sliding Window。

## 核心思維與 Invariant

### 維護的狀態

| 型態 | 核心狀態 | Invariant（每輪開始時成立的敘述） |
| --- | --- | --- |
| 有序 pair sum | `left`、`right` | 若答案尚未找到，仍有可能的配對都在 `[left, right]` 內 |
| 反轉／回文 | 兩端與未處理區間 | 區間外的對稱位置已交換完成，或已通過比較 |
| 原地篩選 | `read`、`write` | `[0, write)` 是原始 `[0, read)` 中應保留的結果，且 `write <= read` |
| 兩序列合併 | 兩個讀取位置、輸出位置 | 已輸出的部分有序，且恰好包含已消耗的元素 |
| 快慢指標 | `slow`、`fast` | 每輪各走一步與兩步；進入環後可追蹤兩者的相對位置 |

不同型態的 invariant 不同，不要把「範圍縮小」當成所有題目的完整證明。

### 狀態如何更新：以有序兩數和為例

假設 `nums` 非遞減排序，且要找不同索引的兩個元素：

```text
sum = nums[left] + nums[right]

sum < target：left++
sum > target：right--
sum == target：依題意回傳、記錄或計數
```

### 為什麼不會遺漏答案

若 `nums[left] + nums[right] < target`，對任何 `left < j <= right`：

```text
nums[left] + nums[j] <= nums[left] + nums[right] < target
```

因此目前 `left` 與剩餘任何位置都不可能組成答案，才能執行 `left++`。

若和太大，對任何 `left <= i < right`：

```text
nums[i] + nums[right] >= nums[left] + nums[right] > target
```

所以目前 `right` 可以被排除。每一步都排除一整批不可能的配對，其餘候選仍留在區間內；當 `left >= right`，已沒有兩個不同索引可配對。

**排序後即使含負數，上述不等式仍成立。** 負數會破壞某些「連續區間和」的視窗規則，並不會破壞這個有序 pair sum 證明。

### 為什麼通常是線性時間

若每輪至少一個指標前進，指標不回頭，且每輪更新為 `O(1)`，一個長度 `n` 的相向掃描最多移動 `O(n)` 次。兩個長度分別為 `m`、`n` 的序列則合計移動 `O(m + n)` 次。

內層有 `while` 不一定是 `O(n²)`；要看總移動次數。但外層每換一個固定元素就重新掃描整段時，仍須乘上外層成本。排序、輸出與每輪額外操作也要另外計入。

---

## 解題流程

1. 確認輸出是存在性、一組答案、不重複值組合，還是所有索引配對的數量。
2. 從暴力枚舉找出可重用的順序關係，判斷是否已排序、能否排序，以及原始順序是否重要。
3. 選擇相向、讀寫、雙序列或快慢指標，寫清楚每個指標代表的狀態。
4. 用一句 invariant 定義已完成部分與尚未處理部分。
5. 對每個分支說明為什麼可以移動；若說不清楚，先不要套模板。
6. 決定相等時的行為：立即回傳、跳過重複值、累加頻率，或保留某一個元素。
7. 確定終止條件與更新順序；檢查交會位置是否還需要處理。
8. 檢查空輸入、重複值、索引基準、整數溢位與排序的副作用，再計算完整複雜度。

## 通用 Java 模板

以下沿用 repo 的 Java 17 設定。方法可放進自己的 class；有 import 的區塊請將 import 放在檔案開頭。輸入預設非 `null`，有序模板要求**實際被掃描的陣列**已排序。

### 1. 相向指標：有序陣列找一組配對

```java
public int[] findPair(int[] sorted, long target) {
    int left = 0;
    int right = sorted.length - 1;

    while (left < right) { // 配對需要兩個不同位置
        long sum = (long) sorted[left] + sorted[right];
        if (sum == target) {
            return new int[] {left, right}; // 可變部分：答案格式
        } else if (sum < target) {
            left++;
        } else {
            right--;
        }
    }
    return new int[] {-1, -1}; // 可變部分：無解的表示方式
}
```

- 固定骨架：兩端初始化、比較、依排除證明移動，直到不再有合法配對。
- 依題目調整：比較關係、找到答案後的處理，以及回傳索引或值。此模板回傳 **0-based** 索引。
- 複雜度：已排序前提下，時間 `O(n)`、額外空間 `O(1)`。若先排序，需另計排序時間與空間。

### 2. 相向指標：一次計入一批配對

計算 `i < j` 且 `sorted[i] + sorted[j] < limit` 的索引配對數：

排序只重排元素，不合併相同值。條件只看兩個值且交換順序不影響結果，所以每組原始索引配對都唯一對應排序後的一組配對，總數不變；若條件還依賴原始索引的距離，就不能套用這個推論。

```java
public long countPairsLessThan(int[] sorted, long limit) {
    int left = 0;
    int right = sorted.length - 1;
    long count = 0;

    while (left < right) {
        long sum = (long) sorted[left] + sorted[right];
        if (sum < limit) {
            count += right - left;
            left++;
        } else {
            right--;
        }
    }
    return count;
}
```

當最大搭配 `sorted[left] + sorted[right]` 都符合時，固定 `left`，所有 `j` 在 `[left + 1, right]` 的配對都符合，一次加上 `right - left`。移動 `left` 後，這一批不會再被計算。

若和不小於 `limit`，固定 `right` 的其他配對只會更大，所以可以移除 `right`。Invariant 是：每個已移出範圍的配對，都已被計入一次或被證明不符合。

- 固定骨架：用單調性批次計數，再移除已處理的一端。
- 可變部分：`<`、`<=`、`>` 對應的分支與批次範圍，必須重新推導，不能只改比較符號而不檢查方向。
- 複雜度：排序後一次掃描 `O(n)`、額外空間 `O(1)`。

區間計數可重用同一個 helper。以下上下界為 `int` 且 `lower <= upper`：

```java
import java.util.Arrays;

public long countPairsInRange(int[] nums, int lower, int upper) {
    int[] sorted = nums.clone();
    Arrays.sort(sorted);
    return countPairsLessThan(sorted, (long) upper + 1)
            - countPairsLessThan(sorted, lower);
}
```

整數和落在 `[lower, upper]` 的數量，等於「小於 `upper + 1`」減去「小於 `lower`」。在加 `1` **之前**轉成 `long`，可避免 `upper == Integer.MAX_VALUE` 時溢位。這個方法與前面的 helper 放在同一個 class。

兩次掃描仍是 `O(n)`；若排序為 `O(n log n)`，總時間為 `O(n log n)`。此版本複製陣列以保留輸入，使用 `O(n)` 額外空間；若允許直接排序輸入，可省去副本，但仍須另計排序實作的空間。

### 3. 同向讀寫：原地保留符合條件的元素

```java
import java.util.function.IntPredicate;

public int retain(int[] nums, IntPredicate keep) {
    int write = 0;
    for (int read = 0; read < nums.length; read++) {
        int value = nums[read];
        if (keep.test(value)) { // 可變部分：是否保留
            nums[write] = value;
            write++;
        }
    }
    return write; // 有效結果是 nums[0..write)，不是整個陣列
}
```

固定骨架是 `read` 每輪前進、只有保留時 `write` 才前進。`write <= read` 保證寫入不會破壞未讀資料，也會保留元素的相對順序。

可變部分是保留條件及尾端處理。例如移除特定值可傳入 `value -> value != removedValue`；搬移零時，先保留非零值，再將 `[write, nums.length)` 填為零。

有序去重時，可改用 `write == 0 || value != nums[write - 1]` 作為保留條件。它依賴已寫入的結果，應直接寫在迴圈內；只有重複值相鄰時，這樣才能去除所有重複。

若 predicate 每次使用 `O(1)` 時間且不修改陣列，時間為 `O(n)`，掃描本身額外空間為 `O(1)`。未使用的尾端不屬於回傳結果，除非題目要求，無須清除。

### 4. 雙序列合併：由後往前寫入

前提：`first` 的前 `m` 個元素與 `second` 的前 `n` 個元素各自有序，且 `first` 容量至少為 `m + n`。兩個輸入是不同陣列。

```java
public void mergeSorted(int[] first, int m, int[] second, int n) {
    int i = m - 1;
    int j = n - 1;
    int write = m + n - 1;

    while (j >= 0) {
        if (i >= 0 && first[i] > second[j]) {
            first[write--] = first[i--];
        } else {
            first[write--] = second[j--];
        }
    }
}
```

Invariant：`[write + 1, m + n)` 已是合併結果的正確後綴；每輪把剩餘最大值放進 `write`。當 `j >= 0` 時，`write = i + j + 1 > i`，所以不會覆蓋 `first` 中尚未讀取的元素。

`second` 用完時，`first` 剩餘的前綴已在正確位置。若 `first` 先用完，則持續搬入 `second`，**包含 `j == 0` 的那一個元素**。

- 固定骨架：比較兩個尚未處理的尾端，取較大值，移動對應讀取指標與輸出位置。
- 可變部分：若輸出是新陣列，可改由前往後取較小值，最後補上兩邊尚未消耗的元素。
- 複雜度：時間 `O(m + n)`，此原地合併版本額外空間 `O(1)`；另開輸出陣列則需 `O(m + n)` 輸出空間。

即使另有第三個寫入索引，核心仍是協調兩個輸入序列的進度。

### 5. 鏈結串列快慢指標：判斷是否有環

```java
import LinkedList.ListNode; // repo 既有節點；LeetCode 提供節點時不需此 import

public boolean hasCycle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;

    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {
            return true;
        }
    }
    return false;
}
```

固定骨架是先檢查快指標能否前進，再各走一步與兩步，最後比較**節點身分**。兩者一開始都指向 `head`，不能在移動前就把相等判定為有環。

若無環，`fast` 會到達尾端。若有環，兩者都入環後，`fast` 每輪相對 `slow` 多前進一步，因此模環長的相對位置必會到達相等。以可到達的不同節點數為 `n`，時間 `O(n)`、額外空間 `O(1)`。

可變部分是停止後要取得的資訊。找中點可沿用步速，但前提是無環；找環入口則須在相遇後，將一個指標移回 `head`，兩者改為每輪一步，再次相遇才是入口。第一次相遇點不一定是入口。

## Worked Example：從移動到批次計數

### 找一組和等於 target 的配對

```text
sorted = [-4, -1, 0, 3, 6, 8], target = 5
```

| `left` | `right` | 目前和 | 判斷與更新 |
| --- | --- | --- | --- |
| 0（-4） | 5（8） | 4 | 最大搭配仍太小，排除 index 0，`left++` |
| 1（-1） | 5（8） | 7 | 最小搭配仍太大，排除 index 5，`right--` |
| 1（-1） | 4（6） | 5 | 找到 0-based 索引 `[1, 4]` |

這不是猜測「往哪裡移動比較有機會」，而是每輪證明目前的一端已經不可能形成答案。

### 計算和嚴格小於 limit 的配對數

```text
sorted = [-2, 0, 1, 3], limit = 3
```

| `left` | `right` | 目前和 | 本輪處理 | 累計 |
| --- | --- | --- | --- | --- |
| 0 | 3 | 1 | 加入 `(0,1)`、`(0,2)`、`(0,3)`，`left++` | 3 |
| 1 | 3 | 3 | 不符合嚴格小於，`right--` | 3 |
| 1 | 2 | 1 | 加入 `(1,2)`，`left++` 後停止 | 4 |

重複值也代表不同索引。例如 `[1, 1, 1]` 中和小於 `3` 的配對有 `3` 組；若跳過重複值，就會少算。

## 常見變形

### 1. 跳過無效字元，再比較兩端

[Q125 Valid Palindrome](https://leetcode.com/problems/valid-palindrome/) 要忽略非英數字元與大小寫。每輪先移動兩端到有效字元，再比較、再向內移動；跳過字元的內層迴圈也需保護交會邊界。

可對照 [Q125.java](Q125.java)。若逐字元正規化並直接比較，掃描時間 `O(n)`、額外空間 `O(1)`；既有版本先對整個字串呼叫 `toLowerCase()`，需考慮建立新字串的 `O(n)` 空間。

### 2. 將已排序資料轉換後，由答案尾端填入

有序陣列的平方不一定仍有序，但絕對值最大的元素一定在剩餘區間的某一端。因此比較兩端平方，把較大的放到答案尾端，每次消耗一個端點。

此時應處理直到 `left > right`；`left == right` 時還有最後一個元素要寫入。參考 [Q977_FollowUp.java](Q977_FollowUp.java)。

### 3. 固定部分元素，再縮成兩數問題

3Sum 固定一個索引後做一次相向掃描；4Sum 固定兩個索引後做一次相向掃描。每組固定索引都會重新掃描，因此掃描成本分別為 `O(n²)`、`O(n³)`。

若題目要的是不重複值組合，固定索引需在同一層跳過重複值，找到答案後也要跳過左右兩側已使用的相同值。例如 4Sum 的第二層應以 `j > i + 1` 判斷是否已走過同層候選，而不是一律用 `j > 0`。

但「索引配對計數」不能照搬這個去重規則；相同值可能產生多個不同答案。若計算兩數和恰好等於目標的數量，可考慮 `countLess(target + 1) - countLess(target)`，並先確認門檻加一不會溢位。

### 4. 不靠排序，而靠最佳值上界排除一端

[Q11 Container With Most Water](https://leetcode.com/problems/container-with-most-water/) 的面積是 `min(height[left], height[right]) * (right - left)`，高度不能排序，因為位置決定寬度。

先更新目前最大面積。若左側較矮，保留左側而只把右界向內移，寬度變小，高度上限仍不超過左側，無法改善答案，所以可以排除左側。兩端同高時，移除任一端都安全。

參考 [Blind75/Q11.java](../Blind75/Q11.java)。時間 `O(n)`、額外空間 `O(1)`；通用實作要依值域判斷乘法是否需先轉成 `long`。

### 5. 同向不一定代表快慢速度不同

讀寫指標各負責「掃描」與「建立結果」；Sliding Window 各負責「右界擴張」與「左界收縮」；鏈結串列快慢指標則維持步速或距離。辨識時先看狀態的語意，再選模板。

### 入門：Q344 [Reverse String](https://leetcode.com/problems/reverse-string/)

- 辨識理由：字元陣列要原地反轉，左右位置一一對應。
- 核心狀態或轉換：`[left, right]` 尚未反轉，外側已就定位。
- 最容易出錯的地方：交換後兩端都要移動；中間單一字元不需交換。
- 一句話解法：`left < right` 時交換兩端，逐步向內。
- 複雜度：時間 `O(n)`、額外空間 `O(1)`。

## 常見錯誤與邊界條件

| 錯誤 | 檢查方式 |
| --- | --- |
| 未排序就按兩數和移動 | 寫出排除一端所需的不等式，確認資料順序真的支持它 |
| 排序了副本，卻掃描原資料 | 追蹤傳入掃描方法的容器；`sort(new ArrayList<>(nums))` 不會排序原本的 `nums` |
| 混淆 `<` 與 `<=` | 用和恰好等於門檻的例子測試；嚴格小於的失敗分支包含相等 |
| 直接排序破壞原始索引或距離 | 先確認答案是否只依賴值的組合；需要原始排列時不可任意排序 |
| `left < right` 一律套用 | 找不同索引配對用 `<`；需要消耗最後一個元素的填值流程通常用 `<=` |
| 相等分支沒有移動或結束 | 每輪都必須有進展，否則全相同元素容易造成無限迴圈 |
| 計數時跳過重複值 | `[1,1,1]` 有三組索引 pair，卻只有一種值 pair；先讀清楚答案定義 |
| 把計數覆寫成 `right - left` | 累加使用 `+=`，並說明每批配對為何互不重疊 |
| 原地合併由前往後覆寫 | 若目的陣列還有未讀資料，優先由尾端填入；檢查 `m = 0`、`n = 0` |
| `long sum = a + b` 仍溢位 | 若 `a`、`b` 是 `int`，先用 `(long) a + b`；平方與乘法同理 |
| Java `List.get(i)` 不一定是 `O(1)` | 模板以陣列為基礎；若是 LinkedList，反覆隨機存取會改變複雜度 |
| 快慢指標用節點值判斷相遇 | 相同值不代表同一節點；檢查 `fast != null && fast.next != null` |

基本檢查組合：空陣列、單元素、兩元素、全相同、全負數、混合正負、剛好等於門檻、無解與大量配對。陣列是否允許為空仍以題目契約為準；回文則另檢查過濾後沒有有效字元的情況。

## 與相似 Pattern 的比較

| 判斷面向 | Two Pointers（本篇的有序配對） | Sliding Window | HashMap | Binary Search | Prefix Sum |
| --- | --- | --- | --- | --- | --- |
| 主要訊號 | 有序 pair、可安全排除端點 | 連續區間、最長／最短／數量 | 找補數或查歷史狀態 | 有序範圍、單調判定、找邊界 | 靜態區間和、兩個累積狀態的關係 |
| 維護狀態 | 左右候選位置 | 左右界與整個視窗的統計 | 值、索引或頻率 | 搜尋區間與中點 | prefix array 或歷史 prefix 摘要 |
| 選擇條件 | 一次移動可排除一批配對 | 邊界移動能安全維護條件 | 無序且可接受額外空間 | 可捨棄一半搜尋空間 | 區間資訊能由前綴相消 |
| 常見成本 | 已排序後掃描 `O(n)` | 每界最多走 `n` 步且更新 `O(1)` 時為 `O(n)` | 單次查找平均 `O(1)`，通常需 `O(n)` 空間 | 單次 `O(log n)`；每個元素各查一次則 `O(n log n)` | 建表 `O(n)`，靜態查詢 `O(1)` |

可操作的選擇規則：

- 無序 Two Sum 且要原始索引：先考慮 HashMap；已有序且要求常數額外空間：相向指標。
- 原地壓縮有效資料：讀寫指標；不要因為同向就額外維護一個視窗。
- 題目是連續區間：先判斷能否單調調整視窗；若含負數且要計算和恰好等於目標的區間數，評估 Prefix Sum + HashMap。
- 每個元素都要查一個有序區間：Binary Search 容易獨立求邊界；若相鄰查詢的邊界也單調，可考慮讓指標沿用位置。
- 有序 pair count 中，`left`、`right` 圈出的是**候選配對範圍**，不是要求整段連續元素都納入答案的 subarray。

延伸閱讀：[Prefix Sum Pattern](../PrefixSum/README.md)、[SlidingWindow 題解](../SlidingWindow/)、[BinarySearch 題解](../BinarySearch/)。

## 一分鐘速查

- **訊號**：有序配對、對稱兩端、原地保序、兩個有序序列、鏈結串列步速或距離。
- **核心 invariant**：已排除的候選不會是遺漏答案；已寫入的結果正確，且未讀資料仍可使用。
- **有序兩數和**：太小 `left++`，太大 `right--`；找到答案後的動作由輸出定義決定。
- **小於門檻的計數**：符合時 `count += right - left`，再 `left++`；不符合時 `right--`。
- **讀寫**：先讀、判斷、必要時寫入並增加 `write`；`read` 每輪前進。
- **合併**：若寫回含未讀資料的陣列，就由後往前填；別漏掉另一陣列的 index `0`。
- **邊界**：配對通常 `left < right`；消耗每個元素時需處理交會點；值去重與索引計數不同。
- **型別與成本**：相加前轉 `long`；排序、複製與輸出空間另計，不因為叫雙指標就一定是 `O(n)` / `O(1)`。
- **選擇規則**：有序負數仍能做 pair sum；含負數的連續區間和不能直接套「太大就縮」的視窗規則。
