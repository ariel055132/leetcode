# HashMap Pattern

## 一句話定義

HashMap 把已處理資料整理成「key 對應的摘要」，讓下一個元素能直接找到需要的歷史資訊，省去反覆掃描。

解題時先回答：**哪些資料應視為同一類？未來需要這一類的什麼資訊？** 前者決定 key，後者決定 value。

本筆記沿用 repo 的 Java 17；先看辨識與 invariant，再到 [Java 模板](TEMPLATES.md) 練習實作。連續區間的代數推導可搭配 [Prefix Sum Pattern](../PrefixSum/README.md)。

## 適用情境

- 在未排序陣列中查找另一個符合精確條件的值，例如 `target - current`。
- 統計元素、字元或某種特徵的出現次數，且需要保留重複資訊。
- 將不同表示方式歸為同一組，例如字元組成相同、相鄰字母位移相同。
- 記住某個值或狀態首次／最近出現的位置。
- 對每個分類維護最大值、最小值等摘要。
- 將連續區間條件改寫成兩個 prefix 的關係，再查找歷史 prefix。

## 不適用情境

- 只問「有沒有出現」：HashSet 通常足夠，不必額外存 boolean。
- key 的範圍很小且固定：例如只有 `a` 到 `z`，`int[26]` 往往更直接。
- 需要排序、前驅／後繼或範圍查詢：考慮排序加 Binary Search，或 TreeMap。
- 資料已排序，且兩端移動能排除候選：Two Pointers 可能省下 map 的空間。
- 未來只會用到全域最大／最小值：用單一變數即可，不需要依 key 分類。
- 題目要求區間、路徑或遞迴關係，但尚未找到可查詢的等價狀態：HashMap 本身不會完成這個建模。

## 題目辨識訊號

| 題目訊號 | key 如何設計 | value 需要保存什麼 |
| --- | --- | --- |
| duplicate、seen before | 原始值 | 只要存在性，用 Set |
| frequency、anagram、相同元素配對數 | 元素或字元 | 頻率 |
| 找另一個數，或回傳一組索引 | 原始值，查詢補數 | 一個合法的歷史索引 |
| group、equivalent、相同特徵 | 正規化 signature | 同組元素列表 |
| 最大／最小配對分數 | 分類特徵 | 該組先前最佳元素 |
| 可轉成 prefix 關係的最長區間 | prefix state | 最早索引 |
| 最近重複、距離上限 | 元素 | 最新索引 |
| subarray sum equals target 的數量 | prefix sum | 歷史 prefix 頻率 |

最重要的自問句：

> 暴力法內層迴圈到底在找什麼？能否用一個精確的 key，直接取得所有候選的必要摘要？

## 核心思維與 Invariant

### 維護的狀態

常見 value 的語意不可混用：

| 狀態 | 精確定義 | 同 key 再次出現時 |
| --- | --- | --- |
| `frequency[key]` | 已處理資料中該 key 的出現次數 | 加一 |
| `firstIndex[key]` | 該 key 第一次出現的索引 | 保留原值 |
| `lastIndex[key]` | 該 key 最近一次出現的索引 | 覆寫成目前索引 |
| `groups[key]` | 已處理且屬於該組的所有元素 | 加入列表 |
| `best[key]` | 該組已處理元素的最佳值 | 依目標取 max／min |

對「目前元素要與先前元素配對」的掃描，invariant 是：**處理索引 `i` 的查詢時，map 恰好摘要了 `[0, i)`，尚未包含 `i`。**

例如找和為 `target` 的 pair，map 保存先前的值與索引；查 `target - nums[i]`，找到的索引自然小於 `i`。

### 狀態如何更新

歷史配對常用的固定骨架：

```text
建立 map 與必要的初始狀態
依序讀取目前元素
    產生目前 key 與想查詢的 key
    用 map 中的歷史摘要更新答案
    將目前元素合併到 map
```

「先查再加入」適用於兩個位置必須不同、歷史狀態不能包含自己的情況。例如 `[3]`、target `6`，若先放入再查，就會把同一個位置用兩次。

更新順序由 invariant 決定，不是所有 map 都必須先查。單純分組可直接加入；Sliding Window 常先加入右端，再移除不合法的左端，直到 map 重新符合目前視窗。

### 為什麼不會遺漏答案

以索引對 `(j, i)`、`j < i` 為例，每組合法 pair 都有唯一的右端 `i`。掃描到 `i` 時，左端 `j` 已存在於歷史狀態，所以查詢所需 key 就能找到它。

能否把多個候選壓縮成一個 value，取決於答案需求：

- 只找一組：保留任一合法索引即可。
- 計算所有索引對：保留頻率；一個 key 可能代表多個答案。
- 最大化同組兩數和：保留先前最大數值即可，較小值不會產生更好的候選。
- 列出所有答案：需保留索引列表，輸出數量本身可能達 `O(n²)`。

分組則需要另一項保證：**兩個元素應在同一組，若且唯若它們的 signature 相等。** 只取字串長度、字元總和等過度粗略的特徵，可能把不同組誤合併。

## 解題流程

1. 寫出暴力法的重複查詢，例如「找之前所有值等於 `x` 的位置」。
2. 把條件轉成可精確查詢的等式，或能代表等價類別的 signature。
3. 明確寫下 `map[key]` 的完整語意，決定存存在性、頻率、索引、列表或最佳值。
4. 決定有效範圍：所有已處理資料、目前視窗，還是尚未被使用的元素。
5. 根據 invariant 安排初始化、查詢、更新及移除的順序。
6. 用重複值與沒有答案的輸入手算；prefix 題另檢查從索引 `0` 開始的區間。
7. 計入產生 key、hash／比較 key、保存 value 與輸出結果的成本。

完整方法、imports 與使用前提見 [TEMPLATES.md](TEMPLATES.md)。依問題選擇固定骨架與可變部分：

| 補數查找 | 查歷史 key，再保存目前值 | `needed` 的關係式；回傳索引或計數 |

### 時間與空間複雜度

令 `n` 為元素數、`d` 為不同 key 數。在 key 建立、hash 與相等比較皆為常數成本，且雜湊分布合理時，每次查找／插入可用平均攤銷 `O(1)` 分析，因此單次掃描的預期時間為 `O(n)`。這不是每次操作都保證最壞 `O(1)`。Java 的基本操作成本前提見 [HashMap 官方文件](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/HashMap.html)。

每個 key 只存一個固定大小摘要時，額外空間為 `O(d)`，最壞 `d = n`。若保存完整列表、字串 signature 或全部答案，需額外計入其總大小。

例如長度 `L` 的字串，排序後當 key 需 `O(L log L)`；建立位移序列或固定字母表的計數 signature 可用 `O(L)`，但 signature 的 hash 與比較也有成本。不能只因外層是一個迴圈就宣稱 `O(n)`。

## 常見變形

### 頻率與可消耗次數

「計算所有 pair」與「每個元素只能用一次」不是同一題：

- 所有相同值 pair：遇到 `x`，答案加上先前 `x` 的頻率，再將頻率加一。
- 可移除的配對：找到補數後，要消耗補數的一次額度；找不到才加入目前值。此時 map 表示尚未配對的元素，可對照 [Q1679](Q1679.java)。

在 `[4, 4, 4]` 中，相同值的索引對有 `3` 組；若每個位置只能用一次，則最多只能取出 `1` 組兩數和為 `8` 的配對。

### 最早索引與最新索引

固定右端 `i` 時，`i - j` 要最大就保留最小 `j`，要找最近的相同狀態則保留最大 `j`。

- 最長區間：`putIfAbsent`，不要覆蓋最早位置。
- 最近重複：查完後 `put`，讓下一輪看到最新位置；可對照 [Q219](Q219.java)。

例如 `[1, -1, 1, -1]` 的 prefix `0` 出現在索引 `-1、1、3`。保留 `-1` 才能在最後得到長度 `4`；若一直覆寫，這個最長區間就會遺失。

### 正規化 signature 與分組

若只關心小寫英文字串的相對位移，可把每一對相鄰字母的差正規化為 `(next - previous + 26) % 26`。例如 `"az"` 與 `"ba"` 都得到差 `25`，屬於同一類；可對照 repo 的 [Q249 分組實作](Q249.java)。

編碼 signature 時保留分隔符；`[1, 11]` 與 `[11, 1]` 若直接串接，都會變成 `"111"`。模板另外編入長度，使空字串與單字元字串也能區分。

### 每組只保留最佳候選

若配對分數是 `current + previous`，對固定 current 而言，只需要同組最大的 previous。先用歷史最佳值算答案，再把 current 納入，避免自己與自己配對。此壓縮必須由評分關係證明，不能對所有 pair 題都只留最大值。

### Prefix State 與 HashMap

區間和等於 `target` 可以改寫成 `previousPrefix = currentPrefix - target`。這時 key 是累積狀態，不是原始元素。

| 題目要求 | value | 初始狀態 | 更新規則 |
| --- | --- | --- | --- |
| 符合條件的區間數量 | prefix 頻率 | `{0: 1}` | 查完後加一 |
| 最長符合條件的區間 | prefix 最早索引 | `{0: -1}` | 查完後 `putIfAbsent` |

這裡的索引代表「處理到哪個元素」；`-1` 表示尚未讀取任何元素。若改用 prefix array 的邊界索引，空 prefix 在 `0`，其餘索引也必須一起改，不能混用。

### Sliding Window 中的 HashMap

map 可以只保存 `[left, right]` 的字元頻率。右端加入、左端移除，直到視窗有效；每次移動都必須同步 map。若用 `map.size()` 當不同字元數，頻率歸零時必須移除 key。

另一種做法存字元的最新索引，遇到重複時更新 `left = max(left, previousIndex + 1)`，避免左界倒退。可用 `"abba"` 檢查最後一個 `a` 的舊位置是否已在視窗外。

## Worked Example

### 相同值的索引對

`nums = [4, 4, 2, 4]`，初始 `frequency = {}`、`answer = 0`。

| 索引 | 目前值 | 查詢前的相同值頻率 | 新增 pair | 累積答案 | 更新後頻率 |
| --- | --- | --- | --- | --- | --- |
| 0 | 4 | 0 | 0 | 0 | `{4: 1}` |
| 1 | 4 | 1 | 1 | 1 | `{4: 2}` |
| 2 | 2 | 0 | 0 | 1 | `{4: 2, 2: 1}` |
| 3 | 4 | 2 | 2 | 3 | `{4: 3, 2: 1}` |

最後三組為 `(0, 1)`、`(0, 3)`、`(1, 3)`。Set 只能知道最後一個 `4` 曾經出現，無法知道它能新增兩組答案。

### 重複 prefix 為什麼要存次數

`nums = [0, 0, 0]`、target `0`，初始 frequency `{0: 1}` 代表空 prefix。

| 讀取位置 | prefix | 查詢到的歷史次數 | 累積答案 | 插入目前 prefix 後 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 1 | 1 | `{0: 2}` |
| 1 | 0 | 2 | 3 | `{0: 3}` |
| 2 | 0 | 3 | 6 | `{0: 4}` |

答案為三段長度 `1`、兩段長度 `2`、一段長度 `3`，共 `6` 段。若先插入目前 prefix，再查詢，每輪都會多算一個空區間。

## 代表題目

以下按學習順序安排，並非 LeetCode 難度標籤。`n` 是輸入元素數、`d` 是不同 key 數；HashMap 解法的時間都採用上述平均雜湊假設。題意連至官方頁面，實作連至目前 repo。

### 入門：Q242 Valid Anagram

[題目](https://leetcode.com/problems/valid-anagram/) · [HashMap 實作](Q242_HashTable.java) · [排序實作](Q242.java)

- 辨識理由：比較的是各字元數量，位置順序不影響答案。
- 核心狀態或轉換：建立第一個字串的字元頻率，再消耗第二個字串的字元。
- 最容易出錯的地方：只比較 Set，會遺漏重複次數；先檢查長度可簡化剩餘次數的判斷。
- 一句話解法：每個字元都能消耗一次且兩字串等長，即為 anagram。
- 複雜度：兩字串長度分別為 `n`、`m`，Map 法預期時間 `O(n + m)`、空間 `O(d)`；題目限定小寫英文時，可改用固定 `int[26]`。

### 入門：Q1512 Number of Good Pairs

[題目](https://leetcode.com/problems/number-of-good-pairs/) · [目前實作](Q1512.java)

- 辨識理由：要計算相同值且 `i < j` 的所有索引對。
- 核心狀態或轉換：目前值先前出現 `c` 次，就新增 `c` 組答案。
- 最容易出錯的地方：把目前值也算進舊頻率，或只記存在性。
- 一句話解法：答案先加舊頻率，再把目前值的頻率加一。
- 複雜度：模板可達預期時間 `O(n)`、空間 `O(d)`；repo 現有版本先 `Arrays.sort`，因此其整體時間為 `O(n log n)`，且會修改輸入順序。

### 標準：Q1 Two Sum

[題目](https://leetcode.com/problems/two-sum/) · [實作中的 twoSumHashMap](../Blind75/Q1.java)

- 辨識理由：對每個目前值，都在找另一個精確的補數。
- 核心狀態或轉換：`value -> 歷史索引`，查詢 `target - value`。
- 最容易出錯的地方：先插入導致同一位置被使用兩次；題目要索引，不能只保存 Set。
- 一句話解法：找到補數就回傳歷史索引與目前索引，否則保存目前值。
- 複雜度：預期時間 `O(n)`、空間 `O(d)`。通用模板另定義無解時回傳 `[-1, -1]`。

### 變形：Q2342 Max Sum of a Pair With Equal Sum of Digits

[題目](https://leetcode.com/problems/max-sum-of-a-pair-with-equal-sum-of-digits/) · [目前實作](Q2342.java)

- 辨識理由：兩數是否可配對取決於 digit sum，目標是最大化配對和。
- 核心狀態或轉換：`digitSum -> 同組先前最大的單一數值`。
- 最容易出錯的地方：value 不是 pair 總和；必須先算配對和，再更新該組最大值。
- 一句話解法：每個數與同 digit sum 的歷史最大值配對，再維護最大值。
- 複雜度：令 `w` 為輸入數值的最大十進位位數，預期時間 `O(nw)`、空間 `O(d)`；固定寬度 `int` 的 `w` 有常數上限。

### 綜合：Q560 Subarray Sum Equals K

[題目](https://leetcode.com/problems/subarray-sum-equals-k/) · [Prefix Sum 實作](../PrefixSum/Q560PrefixSum.java)

- 辨識理由：計數連續區間的精確總和，且可能有負數。
- 核心狀態或轉換：`prefix -> 次數`，查詢 `currentPrefix - k`。
- 最容易出錯的地方：漏掉空 prefix、把頻率改成 boolean，或先加入再查詢。
- 一句話解法：從空 prefix 開始，累加符合條件的歷史次數後再登記目前 prefix。
- 複雜度：預期時間 `O(n)`、空間 `O(n)`；模板用 running prefix，repo 版本另建 prefix array，兩者的空 prefix 表示方式不同但都只加入一次。

### 綜合：Q525 Contiguous Array

[題目](https://leetcode.com/problems/contiguous-array/) · [Prefix Sum 實作](../PrefixSum/Q525PrefixSum.java)

- 辨識理由：二元陣列中，求 `0` 與 `1` 數量相等的最長連續區間。
- 核心狀態或轉換：把 `0` 視為 `-1`、`1` 視為 `+1`；相同 prefix 之間的總和為 `0`。
- 最容易出錯的地方：要存最早索引而非頻率或最新索引；repo 使用 prefix 邊界索引，模板使用元素索引。
- 一句話解法：用目前索引減去同 prefix 的最早索引，更新最大長度。
- 複雜度：預期時間 `O(n)`、空間 `O(n)`。

## 常見錯誤與邊界條件

| 錯誤 | 如何檢查或修正 |
| --- | --- |
| value 的語意不清楚 | 用一句話定義它保存的是次數、位置、列表還是最佳值 |
| 混用 `put` 與 `putIfAbsent` | 最新位置要覆寫，最早位置要保留 |
| 補數或 prefix 把自己算進去 | 用單元素 `[3]`、target `6`，及 `[0]`、target `0` 檢查順序 |
| 頻率歸零卻仍計入可用元素／種類 | 若靠 `containsKey` 或 `size()` 判斷可用元素／種類，歸零時移除 |
| `Integer` 使用 `==` 比數值 | 對兩個包裝物件使用 `.equals`，或安全拆箱後比較 |
| `Map<Long, ...>` 查詢用 `0` | 使用 `0L`；`get(Object)` 可接受 Integer，但它不會等於 Long key |
| 把沒有對應值直接拆箱 | 先檢查 `null` 或使用 `getOrDefault`；本筆記模板不存 null value |
| 把 `containsValue` 當作快速反查 | 反向查詢頻繁時，另建反向 map；不要在每輪掃描所有 value |
| key 編碼遺失資訊 | 檢查分隔符、長度、負號、循環位移；不要只存原資料的 hashCode |
| 使用陣列或可變物件作 key | `int[]` 不按元素內容判等；改用穩定的字串或正確實作相等語意的不可變 key |
| 依賴 HashMap 的遍歷順序 | 需要固定輸出順序時明確排序，或依需求選擇 LinkedHashMap／TreeMap |
| 數值溢位 | 補數運算先轉 `long`；prefix、pair 和答案可能超出 `int` |

HashMap 不保證遍歷順序，`get` 回傳 null 也可能代表 key 對應的 value 是 null；相關語意見 [HashMap 官方文件](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/HashMap.html)。key 放入後若改變其相等比較的結果，map 行為沒有保證，見 [Map 官方文件](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Map.html)。

Hash 碰撞本身不表示兩個 key 相等：正常的 HashMap 仍會判斷 key 相等性。真正危險的是自行把不同狀態編成相同 signature，因為那時 map 已無法還原丟失的資訊。

至少手算空輸入、單元素、全相同、全不同、零、負數、無解及答案數量很大的輸入。確認題目是否允許這些情況；通用模板的輸入前提與無解回傳值均寫在模板檔案中。

## 與相似 Pattern 的比較

| 方法 | 維護的狀態 | 優先選擇的條件 | 需要注意 |
| --- | --- | --- | --- |
| HashMap | key 對應的摘要 | 精確查找，且需要次數、索引或群組資訊 | key 設計與摘要是否足夠 |
| HashSet | 出現過的 key | 只問存在性或去重 | 不能保留重複次數與位置 |
| 計數陣列 | 固定值域中的頻率 | 值域小且可直接當索引 | 值域過大會浪費空間 |
| 排序加 Two Pointers | 有序資料與兩端位置 | 已排序，或排序可接受且能單調排除候選 | 排序成本、原始索引與輸入是否可修改 |
| Sliding Window | 目前連續區間與左右界 | 可證明移動左界不會漏掉所需答案 | map 只是一種維護視窗的工具 |
| Prefix Sum 加 HashMap | 歷史累積狀態 | 精確區間關係，尤其 sum 可含負數 | 先推導等式，再決定存頻率或索引 |
| TreeMap | 有序 key 與對應值 | 需要前驅、後繼或有序範圍 | 基本查找與更新為 `O(log d)` |

可操作的選擇規則：先判斷是否需要「相等」還是「大小關係」；精確查找再分辨是只問存在性，還是需要附帶資料。對連續區間題，先決定用 Sliding Window 或 Prefix Sum 建模，再選擇 map 的角色。

## 一分鐘速查

- 訊號：頻率、補數、重複、分組、歷史位置、相同 prefix。
- 定義：**key 決定誰算同一類；value 決定要留下什麼資訊。**
- 核心 invariant：歷史配對在查詢時只包含先前元素；視窗 map 則只摘要有效視窗。
- 骨架：產生 key → 查詢歷史並更新答案 → 合併目前元素。
- 更新：計數加一；最早索引用 `putIfAbsent`；最新索引用 `put`；每組最佳值取 max／min。
- Prefix：計數初始 `{0: 1}`，最長區間的元素索引初始 `{0: -1}`。
- 邊界：不能自己配自己、不能丟失重複次數、signature 不可混淆不同組、計數與總和注意 `long`。
- 選擇：只問有沒有，用 Set；值域固定且小，用陣列；要有序查詢，考慮 TreeMap。
- 複雜度：`O(n)` 依賴常數 key 成本與平均雜湊假設，字串與輸出成本要另算。
